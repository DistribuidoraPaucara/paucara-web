📢 Sistema de Notificaciones Recurrentes - Guía Completa

🎯 Descripción General

Sistema completo de notificaciones recurrentes que permite enviar anuncios, promociones y ofertas a todos los usuarios de la app móvil en tiempo real, sin costo de Firebase.

Características:

  • ✅ Notificaciones en tiempo real (<100ms)
  • ✅ Envío automático por scheduler (cron)
  • ✅ Panel web para gestionar notificaciones
  • ✅ Push nativas en Android + iOS
  • ✅ $0 de costo (usando infraestructura existente)

📋 Fases de Implementación

Fase 1: Backend Laravel ✅

Archivos:

  • app/Models/NotificacionRecurrente.php - Modelo con lógica de recurrencia
  • app/Http/Controllers/NotificacionRecurrenteController.php - CRUD + envío
  • app/Events/NotificacionRecurrenteEmitida.php - Evento de broadcasting

  • database/migrations/2026_08_04_...create_notificaciones_recurrentes_table.php

  • routes/api.php - Endpoint GET /api/notificaciones/pendientes

Base de datos:

notificaciones_recurrentes
├── id
├── titulo
├── descripcion
├── tipo (promocion, informativo, evento, oferta)
├── frecuencia (una_vez, diario, semanal, mensual)
├── hora_envio (HH:mm)
├── dias_semana (JSON, para semanal)
├── dia_mes (para mensual)
├── fecha_inicio
├── fecha_fin
├── activo (boolean)
├── total_enviadas (counter)
├── vistas (counter)
├── ultimo_envio (datetime)
└── usuario_id (admin que la creó)

🚀 Guía de Uso - Panel Web Admin

1. Acceder al Panel

URL: http://tu-servidor/admin/notificaciones-recurrentes
Permiso requerido: admin

2. Crear una Notificación

Paso 1: Click en botón "Crear Notificación"

Paso 2: Completar formulario:

Título: "Descuento de fin de semana" (máx 255 caracteres)
Descripción: "20% en todos nuestros productos" (permite HTML)
Tipo: Promocion / Informativo / Evento / Oferta
Frecuencia: Una vez / Diario / Semanal / Mensual

Si frecuencia es "Semanal":
  → Seleccionar días: Lunes, Martes, Miércoles, etc.

Si frecuencia es "Mensual":
  → Día del mes: 1-31

Hora de envío: 10:30 (formato 24hs)
Fecha inicio: 2026-08-04
Fecha fin: (opcional, si está vacía = sin límite)
Activo: ✓ (checkbox)

Paso 3: Click "Guardar"

3. Enviar una Notificación

Opción A: Envío Manual Inmediato

1. Ir a listado de notificaciones
2. Click en el icono postal (📮) en la fila de la notificación
3. Se envía instantáneamente a todos los usuarios conectados
4. Ver confirmación: "✅ Notificación enviada exitosamente"

Opción B: Envío Automático por Scheduler

El servidor ejecuta automáticamente cada minuto:
  php artisan schedule:run

El comando "notificaciones:enviar" verifica:
  ✓ Notificaciones activas y dentro del rango de fechas
  ✓ Hora actual coincide con hora_envio configurada
  ✓ No se ha enviado hoy (para recurrentes)
  
Si todo cumple → Se envía automáticamente a todos

4. Ver Estadísticas

En el dashboard superior:

  • Total: Todas las notificaciones creadas
  • Activas: Con activo=true
  • Inactivas: Con activo=false
  • Próximas: Activas y dentro del rango de fechas

En la tabla:

  • Columna "Enviadas": Cantidad enviada + vistas entre paréntesis
  • Ejemplo: 5 (3) = enviada 5 veces, vista 3 veces

5. Ejemplos Prácticos

Promoción Diaria a las 9:00 AM

Título: Oferta del día
Tipo: Promocion
Frecuencia: Diario
Hora: 09:00

Título: Resumen semanal
Tipo: Informativo
Frecuencia: Semanal
Días: Lunes, Viernes
Hora: 08:00
Activo: ✓

→ Lunes y viernes a las 8:00 AM (recurrente)

🐛 Troubleshooting

Problema: "La notificación no llega a la app"

Soluciones:

1. Verificar WebSocket conectado
   → Console Flutter: "✅ Socket conectado"
   
2. Verificar app está en foreground
   → Las notificaciones de fondo requieren setup adicional
   
3. Verificar permisos de notificaciones
   → Android: Configuración → Aplicaciones → Distribuidora → Permisos
   → iOS: Configuración → Notificaciones → Distribuidora
   
4. Verificar servidor WebSocket corriendo
   → curl http://tu-ip:3001/api/broadcast
   → Response: {"status":"ok"}
   
5. Verificar Laravel enviando a WebSocket
   → Logs: storage/logs/laravel.log
   → Buscar: "HTTP POST /api/broadcast"

Problema: "Error de conexión WebSocket"

Soluciones:

1. Verificar IP y puerto correcto en .env
   WEBSOCKET_URL=http://tu-ip:3001
   
2. Verificar firewall abierto
   → Puertos: 8000 (Laravel), 3001 (WebSocket)
   
3. Verificar CORS en Node.js
   → socket/src/config/cors.config.js
   
4. Verificar token Sanctum válido
   → El app envía: Authorization: Bearer {token}
   → Server valida contra PostgreSQL

Problema: "Notificaciones con duplicados"

Soluciones:

1. Verificar scheduler no se ejecuta múltiples veces
   → Verificar cron configuration
   → Verificar procesos Node/PHP background
   
2. Verificar base de datos
   → SELECT * FROM notificaciones_recurrentes
   WHERE id = X AND ultimo_envio::date = TODAY()
   
3. Limpiar duplicados (si ocurrió)
   → php artisan movimientos:limpiar-duplicados

Métricas Clave

Total enviadas por día:     SELECT COUNT(*) FROM notificaciones_recurrentes 
                             WHERE DATE(ultimo_envio) = TODAY()

Total vistas:               SELECT SUM(vistas) FROM notificaciones_recurrentes

Tasa de visualización:      SUM(vistas) / SUM(total_enviadas) * 100

Tipo más popular:           SELECT tipo, COUNT(*) 
                             FROM notificaciones_recurrentes 
                             GROUP BY tipo ORDER BY COUNT(*) DESC

🔐 Seguridad

Autenticación

  • ✅ Requiere login en web admin
  • ✅ Permiso 'admin' requerido
  • ✅ WebSocket valida token Sanctum vs PostgreSQL
  • ✅ API endpoints protegidos por middleware

Autorización

  • ✅ Solo admins pueden crear/editar/enviar
  • ✅ Broadcasting es global (todos reciben si están conectados)
  • ✅ No hay datos sensibles en el payload

Validación

  • ✅ Título máx 255 caracteres
  • ✅ Descripción validada HTML
  • ✅ Tipo: whitelist de 4 opciones
  • ✅ Frecuencia: whitelist de 4 opciones
  • ✅ Hora: formato 24hs HH:mm
